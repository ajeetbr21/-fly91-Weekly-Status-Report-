# Word report design-match: cover, cost-table merges, config-driven assets (v1)

This branch rebuilds the Word report so it visually tracks the client's original file: a professional cover page (blue left accent bar, logo top-right, large title) on page 1, a "Cost Summary Differences" table reconstructed to match the screenshot (centered+underlined title, stacked `N`/`o` header, two-line bold Last/Current Week date headers, vertically-merged account-identity cell, a merged `Total Cost` row), US Letter page size with reference-aligned margins, and a `word_report.assets` config mapping so the client can swap logo/screenshots without code changes. Inspector/GuardDuty/cost visuals now prefer the configured screenshots and fall back to the runtime Pillow renderer. The design code is unconditional on the `--mock` flag, so mock and real-data documents share the exact same structure.

Watch for: the cover's blue "vertical accent bar" is only one text-line tall, not a full-height left-edge bar as in the screenshot — the helper named `_set_cell_vertical_bar_height` never sets a height (confirmed). Everything else matches the two screenshots and degrades gracefully on missing assets.

**Verdict**: NEEDS_CHANGES

## High-level view

The design is driven entirely from `collected_data` and static layout code — nothing branches on the mock flag, and a freshly generated `--mock` document passes the same OOXML design assertions as the committed demo, so the "identical design for mock vs real" requirement holds. On real AWS data in CloudShell only the cell values change.

The cost table matches the screenshot structurally: underlined centered title, stacked `N`/`o`, two-line bold date headers with `w:br`, a `w:vMerge` account-identity cell spanning the service rows, and a `gridSpan`-merged `Total Cost` leading cell with `(... Tax Excluded Cost)` totals. All verified in the generated XML.

The cover is the one place where the output deviates from the screenshot. The logo embeds top-right and a `1F4E79` fill is applied to the left cell, but that cell has no row height, so the "blue bar" is a short stub rather than a bar running down the page edge. The full-page cityscape background is a documented known gap (not shipped); its OOXML anchor code only runs when the client supplies `assets/cover_background.png`, so it's untested in this build.

Asset resolution and every OOXML helper are wrapped so a missing file or a helper failure is logged and skipped rather than aborting the document, and the Excel path and `--format` flag are untouched.

### Data-agnostic design verified against the mock output

The requirement that drove this whole branch — "design ekdam same whether mock or real" — holds. `report/word_report.py` has zero references to the mock flag; the cover, page setup, font, table merges and header builders all run off `self.word_cfg` and the `cost` dict regardless of data origin. Generating a fresh `--mock` document and running `scripts/verify_word_report.py <docx> --min-images 7` reproduces `ALL CHECKS PASSED tables=8 paras=63 images=7`, identical to the committed demo, including every new `design:` assertion (underlined+centered title, `vMerge`, `gridSpan`, two-line headers with `w:br`, `pgSz` 12240x15840, stacked `N`/`o`). On CloudShell with real credentials and no `--mock`, only the per-service cost values and totals change; the structure is produced by the same code path. (confirmed)

### Cost table matches the screenshot

### Cover deviates: accent bar height

The cover uses a borderless 1×2 table (no `style` set, so no `Table Grid` borders — correct for an invisible layout table), shades the left cell `1F4E79`, and right-aligns the logo at 1.8in. The problem is the bar height. `_set_cell_vertical_bar_height` is named and documented as giving the cell "a tall minimum height so the blue column reads as a full-height vertical bar," but the body only strips run text:

```python
def _set_cell_vertical_bar_height(cell) -> None:
    tc_pr = cell._tc.get_or_add_tcPr()          # fetched, never used
    for paragraph in cell.paragraphs:
        for run in list(paragraph.runs):
            run.text = ""
```

No `w:trHeight` / row height is set — the generated demo has `trHeight` count 0. The result is a short blue stub beside the logo rather than a bar down the left edge. This is the one visible miss against the screenshot. (confirmed)

### Graceful degradation and asset resolution

`_asset_path` resolves logical names against the repo root and returns a path only when the file exists, so a missing asset means the caller skips that image. The Inspector and GuardDuty builders prefer the configured screenshots and fall back to the runtime Pillow renderer when assets are absent (Inspector only short-circuits the fallback when at least one severity asset embedded). Page setup, default font, cell shading, merges and centering are each wrapped so an OOXML failure is logged and skipped instead of aborting the document. The cover background anchor is likewise guarded, but since `cover_background.png` is intentionally not shipped, that hand-built `wp:anchor` path doesn't execute in this build and hasn't been exercised end-to-end — worth one manual check with a real image before the client depends on it. (confirmed for degradation; possible for the untested anchor path)

### Excel path and CLI untouched

Nothing in this diff touches the Excel generator or the `--format {docx,xlsx,both}` flag; a `--format both` mock run produced both outputs without error. The Word output filename still comes from `word_report.word_output_filename` rather than `--output`, so `--output` only names the Excel file — this is pre-existing behavior on `main`, not a regression introduced here, so it's out of scope. New type hints use `Optional[...]` with no `X | None` unions, so the Python 3.9 constraint holds. (confirmed)
